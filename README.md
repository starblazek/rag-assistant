# AI Tutor

`AI Tutor` — локальный консольный помощник для обучения, написанный на Python и работающий через Ollama. Он отвечает на вопросы, опираясь только на материалы курса из папки `knowledge/`.

Проект использует подход retrieval-augmented generation (RAG): извлекает текст из учебных файлов, разбивает его на фрагменты, создаёт локальные эмбеддинги, находит наиболее релевантные фрагменты по вопросу и передаёт их локальной языковой модели в качестве контекста.

## Возможности

- Работает локально через Ollama.
- Использует `qwen3:8b` для ответов в чате и `bge-m3` для эмбеддингов.
- Загружает учебные материалы в форматах TXT, PDF, DOCX и PPTX.
- Сохраняет доступные сведения об источнике: страницы PDF, слайды PowerPoint, абзацы и таблицы DOCX.
- Выполняет поиск по эмбеддингам с помощью косинусного сходства.
- Добавляет названия источников и их расположение в контекст, отправляемый модели.
- Хранит историю диалога в локальном JSON-файле.
- Поддерживает команды `/clear`, `/history` и `/exit`.

## Архитектура

```text
Подготовка материалов:
knowledge/ → loaders → sections → splitter
→ storage/chunks.json → vectorize (bge-m3) → chunks.json с эмбеддингами

Ответ на вопрос:
вопрос пользователя → embedding (bge-m3)
→ cosine similarity с chunks.json → top-3 подходящих фрагмента
→ context.py (источники и расположение)
→ system prompt + история + контекст → qwen3:8b → терминал
```

Основные модули:

| Путь | Назначение |
| --- | --- |
| `main.py` | Цикл взаимодействия с пользователем в терминале. |
| `chat.py` | Формирует сообщения для модели из системного промпта, найденного контекста и истории. |
| `context.py` | Форматирует найденные фрагменты и сведения об источниках. |
| `llm.py` | Отправляет запросы к Ollama. |
| `memory.py` | Загружает, сохраняет и очищает историю диалога. |
| `rag/index.py` | Загружает материалы курса и записывает текстовые фрагменты. |
| `rag/vectorize.py` | Создаёт и сохраняет эмбеддинг для каждого фрагмента. |
| `rag/retriever.py` | Находит фрагменты с наибольшим сходством с вопросом. |
| `rag/loader/` | Загрузчики для отдельных форматов файлов. |

## Требования

- Python 3
- [Ollama](https://ollama.com/), установленный и запущенный локально
- Следующие модели Ollama:

```powershell
ollama pull qwen3:8b
ollama pull bge-m3
```

## Установка

Склонируйте репозиторий и создайте виртуальное окружение:

```powershell
git clone https://github.com/starblazek/rag-assistant
cd ai_tutor
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Зависимости Python перечислены в `requirements.txt`:

- `ollama`
- `pypdf`
- `python-docx`
- `python-pptx`

## Настройка

Параметры проекта находятся в `config.py`:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_URL` | `http://localhost:11434` | Объявленный адрес локального сервера Ollama; текущие вызовы клиента не передают этот параметр явно. |
| `MODEL_NAME` | `qwen3:8b` | Чат-модель. |
| `EMBEDDING_MODEL` | `bge-m3` | Модель эмбеддингов. |
| `MAX_HISTORY` | `20` | Настроенный лимит истории. |
| `CHUNK_SIZE` | `500` | Число символов в одном фрагменте. |
| `CHUNK_OVERLAP` | `100` | Перекрытие соседних фрагментов. |
| `TOP_K` | `3` | Максимальное число найденных фрагментов. |
| `SIMILARITY_THRESHOLD` | `0.78` | Минимальный порог косинусного сходства для результата. |

`knowledge/` и `storage/` — локальные папки проекта; Git их игнорирует.

## Добавление учебных материалов

1. Поместите файлы `.txt`, `.pdf`, `.docx` или `.pptx` непосредственно в `knowledge/`.
2. Создайте фрагменты из материалов:

   ```powershell
   python rag/index.py
   ```

3. Создайте эмбеддинги для фрагментов:

   ```powershell
   python rag/vectorize.py
   ```

После добавления или изменения материалов выполните обе команды заново. Индексация записывает данные в `storage/chunks.json`, а векторизация добавляет к ним эмбеддинги.

Текущий загрузчик просматривает только файлы, лежащие непосредственно в `knowledge/`, и не обходит вложенные папки. Неподдерживаемые и пустые документы выводятся в терминале.

## Запуск приложения

После индексации и векторизации материалов запустите CLI:

```powershell
python main.py
```

Введите вопрос в приглашении `Введите текст:`. Ассистенту задано отвечать только по найденным материалам курса и сообщать, если в курсе нет нужной информации.

## Команды CLI

| Команда | Результат |
| --- | --- |
| `/clear` | Очищает локальную историю диалога. |
| `/history` | Выводит текущую локальную историю диалога. |
| `/exit` | Завершает работу приложения. |

## Локальные данные

Приложение создаёт локальные данные в `storage/`:

| Файл | Содержимое |
| --- | --- |
| `storage/chunks.json` | Текстовые фрагменты материалов и их эмбеддинги. |
| `storage/history.json` | История диалога. |

Материалы курса из `knowledge/` и сгенерированные файлы из `storage/` не хранятся в Git.

## Ограничения

- Это терминальное приложение: веб- или графического интерфейса нет.
- Поиск реализован как прямое сравнение JSON-хранимых эмбеддингов по косинусному сходству, без векторной базы данных.
- Поддерживаются только файлы TXT, PDF, DOCX и PPTX.
- Поиск материалов не рекурсивный: файлы во вложенных папках `knowledge/` не загружаются.
- Информация о местоположении в источнике доступна только там, где её формирует загрузчик: для TXT указывается формат, а для PDF, PPTX и DOCX — страница, слайд, абзац или таблица, если применимо.
- История хранится локально в JSON. Хотя `MAX_HISTORY` задан в конфигурации, текущая реализация возвращает всю сохранённую историю.
- При ошибке чат-запроса к Ollama CLI возвращает `Ошибка Ollama`. Ошибки создания эмбеддингов и поиска отдельно не обрабатываются.
